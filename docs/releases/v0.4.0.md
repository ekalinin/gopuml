# gopuml v0.4.0

The fourth release of gopuml, a Go reimplementation of
[PlantUML](https://plantuml.com) v1.2026.9 (MIT variant). It reads the same
diagram language and produces the same SVG, PNG and text output, as a command
line that replaces `java -jar plantuml.jar`, a Go library, an HTTP server and
a WebAssembly module. No JVM and no Graphviz are needed.

## Changes since v0.3.0

- No Graphviz is needed: class, object, use case, component, deployment,
  state, legacy activity and Chen EER diagrams are laid out in the process by
  [gogv](https://github.com/ekalinin/gogv) v0.2.0, a Go implementation of
  Graphviz `dot`. A `dot` named by `--dot-path`, `GRAPHVIZ_DOT` or the library
  option `Options.DotPath` lays them out instead; a `dot` on `PATH` is no
  longer used
- The WebAssembly module lays these diagrams out with gogv too, so they render
  there, and in the playground of the landing page, as in the native build
- `--check-graphviz` without a named `dot` reports gogv:
  `GraphViz: dot - graphviz version 16.1.0 (gogv 0.2.0)`
- Dot diagrams (`@startdot`), drawn by the layout engine itself as upstream
  does: their SVG in the `INTERNET_WITH_DOTSVG` and `INSECURE` security
  profiles and upstream's "This feature has been suppressed" notice in the
  other profiles, and their PNG with a named `dot`
- `@startchronology` gives upstream's "Diagram not supported by this release
  of PlantUML" diagram, as upstream does, instead of a "chronology diagrams
  are not supported yet" error image
- Renders allocate 36-77% fewer bytes and take 5-27% less time, depending on
  the diagram type, without any change of their output
- CI compares the render benchmark of every pull request with its base
  (`make bench-compare`)

## Supported diagrams and formats

| Diagram type | SVG | PNG | TXT / UTXT |
|---|---|---|---|
| Sequence | yes | yes | yes |
| Class and object | yes | yes | no |
| Use case, component and deployment | yes | yes | no |
| State | yes | yes | no |
| Activity (new syntax) | yes | yes | no |
| Activity (legacy syntax) | yes | yes | no |
| Packet | yes | yes | no |
| Gantt | yes | yes | yes |
| Mindmap | yes | yes | no |
| WBS | yes | yes | yes |
| Timing | yes | yes | no |
| Salt | yes | yes | no |
| Chen EER | yes | yes | no |
| Dot | yes, in the `INTERNET_WITH_DOTSVG` and `INSECURE` profiles | with a named `dot` | no |

The preprocessor (`!include`, `!define`, functions, all 74 builtins, JSON),
themes, skin parameters, styles and creole are supported, including diagrams
embedded in text with `{{` ... `}}`, and so is the PREPROC output
(`--preproc`).

The standard library of upstream v1.2026.9 is bundled (`!include
<C4/C4_Container>`, `!include <awslib/AWSCommon>` and the other libraries that
`plantuml -stdlib` lists), apart from nine libraries whose license could not
be verified or does not allow bundling them (see `NOTICE`).

## Not supported yet

Other diagram types (archimate, JSON, and so on) are reported with an
explicit "... diagrams are not supported yet" error image instead of a wrong
drawing. Command line flags that this implementation does not provide (for
example `--pdf`) are rejected with exit status 1.

The internal sprites of the jar (the archimate icons) and the drawing of
OpenIconic icons and emoji are not included yet.

## Graphviz

Class, object, use case, component, deployment, state, legacy activity and
Chen EER diagrams are laid out by gogv, a Go implementation of Graphviz `dot`
that is built into the command line, the library and the WebAssembly module,
so no Graphviz is needed. A Graphviz `dot` named by `--dot-path` (or the
library option) or by the `GRAPHVIZ_DOT` environment variable lays them out
instead; a `dot` on `PATH` is not used. Name one to get upstream's exact
layout, or orthogonal lines with `skinparam linetype ortho`, which gogv does
not support yet and draws as splines. `./plantuml --check-graphviz` reports
the engine in use. Sequence diagrams, activity diagrams in the new syntax,
packet diagrams, gantt diagrams, mindmap diagrams, WBS diagrams, timing
diagrams and salt diagrams do not need a graph layout.

Dot diagrams (`@startdot`) are drawn by the layout engine itself, as upstream
does: gogv, or the `dot` named by `--dot-path` or `GRAPHVIZ_DOT`. Their SVG
needs the `INTERNET_WITH_DOTSVG` or `INSECURE` security profile
(`PLANTUML_SECURITY_PROFILE`); in the other profiles, which include the
defaults of the command line, the library, the server and the WebAssembly
module, it is upstream's "This feature has been suppressed" notice. Their PNG
needs a named `dot`, as gogv does not write PNG yet
([ekalinin/gogv#33](https://github.com/ekalinin/gogv/issues/33)): without one,
it is upstream's "GraphViz has crashed" image.

## Conformance

`make conformance REQUIRE=all` compares this release with upstream PlantUML
v1.2026.9 on 988 cases (upstream's Vega test corpus plus curated cases):

- 928 cases pass
- 55 cases are documented known differences
  (`testdata/conformance/known-differences.yaml`)
- 5 cases are diagram types that are not supported yet
- 0 cases fail

The references were made with Graphviz 14.0.1. 12 of the known differences
are graphs that gogv lays out differently
([ekalinin/gogv#28](https://github.com/ekalinin/gogv/issues/28)), and one is a
dot diagram with `shape=record`, `fillcolor` and `style=filled`, which gogv
does not support yet.

## Comparison with upstream

`make bench` runs the command line of this release and the upstream jar on
the same machine, with the same `dot` for both, so gopuml lays graphs out
with this `dot` here, not with gogv. The start time is the median time of
separate processes that each render a small sequence diagram with
`-tsvg -pipe`. The rendering time of a diagram type is the median time of one
process that renders the curated conformance cases of that type with
`-tsvg -o <dir>`; both use their default of one thread per processor. The
numbers depend on the machine.

| | PlantUML 1.2026.9 (Java) | gopuml |
|---|---:|---:|
| Start time (one small sequence diagram) | 705 ms | 15 ms |
| Rendering: sequence (91 cases) | 965 ms (11 ms per case) | 127 ms (1.4 ms per case) |
| Rendering: class (23 cases) | 908 ms (39 ms per case) | 86 ms (3.7 ms per case) |
| Rendering: description (16 cases) | 1.08 s (68 ms per case) | 145 ms (9.1 ms per case) |
| Rendering: state (21 cases) | 927 ms (44 ms per case) | 130 ms (6.2 ms per case) |
| Rendering: activity (30 cases) | 894 ms (30 ms per case) | 115 ms (3.8 ms per case) |
| Rendering: packet (17 cases) | 780 ms (46 ms per case) | 23 ms (1.4 ms per case) |
| Rendering: gantt (68 cases) | 877 ms (13 ms per case) | 29 ms (0.4 ms per case) |
| Rendering: mindmap (30 cases) | 752 ms (25 ms per case) | 19 ms (0.6 ms per case) |
| Rendering: wbs (40 cases) | 779 ms (19 ms per case) | 21 ms (0.5 ms per case) |
| Rendering: timing (68 cases) | 852 ms (13 ms per case) | 45 ms (0.7 ms per case) |
| Rendering: salt (39 cases) | 740 ms (19 ms per case) | 19 ms (0.5 ms per case) |
| Rendering: chen_eer (31 cases) | 844 ms (27 ms per case) | 89 ms (2.9 ms per case) |

- Machine: darwin/arm64, Apple M3 Pro, 12 CPUs
- Java: openjdk version "25.0.4.1" 2026-08-18 LTS
- Go: go1.27.3
- Graphviz: dot - graphviz version 15.0.0 (20260523.1842)
- Runs: median of 10 start runs and of 5 rendering runs per type

Some curated cases are errors by design (for example syntax errors, a failing
assertion, a missing include or library, an unknown theme, a transition out
of a region, an unknown task or player, a bad indentation) or have no
diagram: both implementations report the same cases and exit with status 200.

## Installation

Each archive of the command line (`gopuml_0.4.0_<os>_<arch>.tar.gz`, `.zip`
on windows) contains the `plantuml` binary, `LICENSE`, `NOTICE` and
`README.md`. `gopuml_0.4.0_wasm.tar.gz` contains `plantuml.wasm`,
`wasm_exec.js`, `plantuml.mjs`, `LICENSE` and `NOTICE`. `checksums.txt` has
the SHA-256 of every archive:

```sh
shasum -a 256 --ignore-missing -c checksums.txt   # sha256sum on linux
tar xzf gopuml_0.4.0_darwin_arm64.tar.gz plantuml
./plantuml --version   # gopuml v0.4.0 (PlantUML 1.2026.9 compatible)
```

The macOS binaries are not signed. When a browser downloaded the archive,
macOS blocks the binary until its quarantine attribute is removed:

```sh
xattr -d com.apple.quarantine plantuml
```

With Go 1.26 or later:

```sh
go install github.com/ekalinin/gopuml/cmd/plantuml@v0.4.0
```
