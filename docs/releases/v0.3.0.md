# gopuml v0.3.0

The third release of gopuml, a Go reimplementation of
[PlantUML](https://plantuml.com) v1.2026.9 (MIT variant). It reads the same
diagram language and produces the same SVG, PNG and text output, as a command
line that replaces `java -jar plantuml.jar`, a Go library, an HTTP server and
a WebAssembly module. No JVM is needed.

## Changes since v0.2.0

- Gantt diagrams (`@startgantt` and `@startproject`), in SVG and PNG, and in
  TXT and UTXT as upstream's table of tasks
- Mindmap diagrams (`@startmindmap`), in SVG and PNG
- WBS diagrams (`@startwbs`), in SVG and PNG, and in TXT and UTXT as
  upstream's text output
- Timing diagrams (`robust`, `concise`, `clock`, `binary` and the other
  players under `@startuml`), in SVG and PNG
- Salt diagrams (`@startsalt`), in SVG and PNG
- Chen EER diagrams (`@startchen`), in SVG and PNG, laid out by Graphviz
  `dot` as upstream does
- Gantt, mindmap, WBS, timing and salt diagrams do not need Graphviz, so they
  also render in the WebAssembly module. There, Chen EER diagrams report that
  graph layout is not available, as the other graph-based diagrams do
- Diagrams of these types can be embedded in text with `{{` ... `}}`, for
  example `{{gantt` or `{{salt` in a note
- `make bench` also measures the rendering time of packet, gantt, mindmap,
  WBS, timing, salt and Chen EER diagrams

## Supported diagrams and formats

| Diagram type | SVG | PNG | TXT / UTXT |
|---|---|---|---|
| Sequence | yes | yes | yes |
| Class and object | yes (needs `dot`) | yes (needs `dot`) | no |
| Use case, component and deployment | yes (needs `dot`) | yes (needs `dot`) | no |
| State | yes (needs `dot`) | yes (needs `dot`) | no |
| Activity (new syntax) | yes | yes | no |
| Activity (legacy syntax) | yes (needs `dot`) | yes (needs `dot`) | no |
| Packet | yes | yes | no |
| Gantt | yes | yes | yes |
| Mindmap | yes | yes | no |
| WBS | yes | yes | yes |
| Timing | yes | yes | no |
| Salt | yes | yes | no |
| Chen EER | yes (needs `dot`) | yes (needs `dot`) | no |

The preprocessor (`!include`, `!define`, functions, all 74 builtins, JSON),
themes, skin parameters, styles and creole are supported, including diagrams
embedded in text with `{{` ... `}}`, and so is the PREPROC output
(`--preproc`).

The standard library of upstream v1.2026.9 is bundled (`!include
<C4/C4_Container>`, `!include <awslib/AWSCommon>` and the other libraries that
`plantuml -stdlib` lists), apart from nine libraries whose license could not
be verified or does not allow bundling them (see `NOTICE`).

## Not supported yet

Other diagram types (archimate, JSON, and so on) are reported with an
explicit "... diagrams are not supported yet" error image instead of a wrong
drawing. Command line flags that this implementation does not provide (for
example `--pdf`) are rejected with exit status 1.

The internal sprites of the jar (the archimate icons) and the drawing of
OpenIconic icons and emoji are not included yet.

## Graphviz

Class, object, use case, component, deployment, state, legacy activity and
Chen EER diagrams are laid out by Graphviz `dot`, as upstream does, so `dot`
must be installed for them. Sequence diagrams, activity diagrams in the new
syntax, packet diagrams, gantt diagrams, mindmap diagrams, WBS diagrams,
timing diagrams and salt diagrams do not need it. The WebAssembly module has
no Graphviz: it reports that graph layout is not available for the diagram
types that need it.

## Conformance

`make conformance REQUIRE=all` compares this release with upstream PlantUML
v1.2026.9 on 972 cases (upstream's Vega test corpus plus curated cases):

- 925 cases pass
- 42 cases are documented known differences
  (`testdata/conformance/known-differences.yaml`)
- 5 cases are diagram types that are not supported yet
- 0 cases fail

## Comparison with upstream

`make bench` runs the command line of this release and the upstream jar on
the same machine, with the same `dot` for both. The start time is the median
time of separate processes that each render a small sequence diagram with
`-tsvg -pipe`. The rendering time of a diagram type is the median time of one
process that renders the curated conformance cases of that type with
`-tsvg -o <dir>`; both use their default of one thread per processor. The
numbers depend on the machine.

| | PlantUML 1.2026.9 (Java) | gopuml |
|---|---:|---:|
| Start time (one small sequence diagram) | 712 ms | 17 ms |
| Rendering: sequence (91 cases) | 1.02 s (11 ms per case) | 132 ms (1.5 ms per case) |
| Rendering: class (23 cases) | 901 ms (39 ms per case) | 108 ms (4.7 ms per case) |
| Rendering: description (16 cases) | 1.13 s (70 ms per case) | 162 ms (10 ms per case) |
| Rendering: state (21 cases) | 932 ms (44 ms per case) | 148 ms (7.0 ms per case) |
| Rendering: activity (30 cases) | 908 ms (30 ms per case) | 123 ms (4.1 ms per case) |
| Rendering: packet (17 cases) | 753 ms (44 ms per case) | 20 ms (1.2 ms per case) |
| Rendering: gantt (68 cases) | 846 ms (12 ms per case) | 43 ms (0.6 ms per case) |
| Rendering: mindmap (30 cases) | 753 ms (25 ms per case) | 21 ms (0.7 ms per case) |
| Rendering: wbs (40 cases) | 757 ms (19 ms per case) | 23 ms (0.6 ms per case) |
| Rendering: timing (68 cases) | 832 ms (12 ms per case) | 72 ms (1.1 ms per case) |
| Rendering: salt (39 cases) | 742 ms (19 ms per case) | 24 ms (0.6 ms per case) |
| Rendering: chen_eer (31 cases) | 841 ms (27 ms per case) | 100 ms (3.2 ms per case) |

- Machine: darwin/arm64, Apple M3 Pro, 12 CPUs
- Java: openjdk version "25.0.4.1" 2026-08-18 LTS
- Go: go1.27.3
- Graphviz: dot - graphviz version 15.0.0 (20260523.1842)
- Runs: median of 10 start runs and of 5 rendering runs per type

Some curated cases are errors by design (for example syntax errors, a failing
assertion, a missing include or library, an unknown theme, a transition out
of a region, an unknown task or player, a bad indentation) or have no
diagram: both implementations report the same cases and exit with status 200.

## Installation

Each archive of the command line (`gopuml_0.3.0_<os>_<arch>.tar.gz`, `.zip`
on windows) contains the `plantuml` binary, `LICENSE`, `NOTICE` and
`README.md`. `gopuml_0.3.0_wasm.tar.gz` contains `plantuml.wasm`,
`wasm_exec.js`, `plantuml.mjs`, `LICENSE` and `NOTICE`. `checksums.txt` has
the SHA-256 of every archive:

```sh
shasum -a 256 --ignore-missing -c checksums.txt   # sha256sum on linux
tar xzf gopuml_0.3.0_darwin_arm64.tar.gz plantuml
./plantuml --version   # gopuml v0.3.0 (PlantUML 1.2026.9 compatible)
```

The macOS binaries are not signed. When a browser downloaded the archive,
macOS blocks the binary until its quarantine attribute is removed:

```sh
xattr -d com.apple.quarantine plantuml
```

With Go 1.26 or later:

```sh
go install github.com/ekalinin/gopuml/cmd/plantuml@v0.3.0
```
